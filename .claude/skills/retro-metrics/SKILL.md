# Retro Metrics — 주간 학습 루프

**이것은 게이트가 아니다.** `harness-audit`과 합치지 않은 이유가 그것이다 —
합치면 회고가 게이트처럼 느껴져 미뤄지고, 게이트가 선택처럼 느껴져 건너뛰게 된다.
여기서는 아무것도 차단하지 않는다. 재고, 분류하고, 다음 주의 후보를 낸다.

주기: 주 1회. **5분 안에 끝나지 않으면 지표를 줄인다** (자를 순서는 M5 → M6).

## Phase 1: 실측

```
node scripts/metrics.mjs report
```

산출물은 `harness/reports/<ISO주차>.md`다. `harness/metrics-baseline.md`에는
**값을 적지 않는다** — 정의만 있는 문서로 유지하는 것이 빈 칸 드리프트의
구조적 해소다.

원천이 셋이라는 것을 리포트에 명시한다. 원천이 다르면 신뢰 수준도 다르다.

| 원천 | 지표 | 주의 |
|---|---|---|
| git | M2 · M5 · M7 | 다른 머신에서 재계산 가능 |
| `phase.jsonl` (커밋됨) | M1(부분) · M3 | 프록시가 아니라 정확한 값 |
| 트레이스 (gitignore) | M6 · M8 | **로컬 전용** — 어느 머신·어느 기간인지 함께 적는다 |

## Phase 2: 최상단에 올릴 것 — force 비율

리포트 맨 위에 **`force` 비율**을 쓴다 (`python harness/phase.py why`가 직접 출력).

> **5% 초과는 에이전트 문제가 아니라 매트릭스가 틀렸다는 신호다.**
> 처방은 사람의 인내가 아니라 정책 수정이다.

`forced:true` 전이가 있으면 각각의 `reason`을 그대로 인용한다. 사유를 요약하지
않는다 — 요약하는 순간 "급해서"가 "일정 압박"이 되고 패턴이 안 보인다.

## Phase 3: M8과 함께 읽기 — 게이트가 하중을 받는가

M8(게이트 차단 횟수)이 **0이면 둘 중 하나이고 둘 다 알아야 한다**:

1. 게이트가 무의미하다 — 아무도 그 경로를 쓰려 하지 않는다 → **제거 후보**.
2. 우회되고 있다 — Bash로 빠져나가고 있다 → **조사 대상**.

판별: `phase-audit.mjs`가 git 이력에서 단계 순서를 독립 재유도한다. 차단 기록은
없는데 이력상 순서가 어긋나 있으면 2번이다.

M8이 특정 경로에 몰려 있으면 그것은 **매트릭스가 틀렸다는 신호**이지 에이전트가
말을 안 듣는다는 신호가 아니다. 정당한 작업이 반복해서 막히면 경로를 연다.

## Phase 4: 실패 분류

`.harness/logs/tools.jsonl`(실패·차단만)과 `trajectory.jsonl`을 훑어 이번 주의
실패를 세 모집단으로 나눈다. **섞으면 처방이 섞인다.**

| 모집단 | 신호 | 처방 주체 |
|---|---|---|
| 환경·배선 파손 | 훅 에러, 스크립트 부재, 인코딩 실패 | 하네스 (`harness-audit`) |
| 정책 차단 | `blocked[]` — 게이트가 의도대로 막음 | 판단: 정당한 차단인가, 매트릭스 오류인가 |
| 헤맴 | `file_edit_counts` 상위 — 같은 파일 6번 수정, Edit 3연속 실패 | 컨텍스트·프롬프트 (테스트는 전부 초록이어도 나타난다) |

테스트 실패는 별도다. `check.mjs --repeat N`이 `assert`/`collect`/`crash`로
분류한다. **`assert` 외의 실패를 "flake"로 뭉뚱그리지 않는다** — 조용히
건너뛴 스위트는 "리팩터가 테스트 로드를 깨뜨렸다"와 구별되지 않는다.

## Phase 5: 골든 승격 후보

이번 주 이상했던 세션의 **입력**을 골든 케이스 후보로 뽑는다. 승격 루프가
작동한다는 증거가 M7이다.

- 트랙 A(제품 행동) 후보 → `evals/golden/track-a-product.jsonl`
- 트랙 B(하네스 행동) 후보 → `evals/golden/track-b-harness.jsonl`

**정답(then/rubric)은 반드시 사람이 쓴다.** `evals/golden/**`는
`permissions.ask` 게이트 뒤에 있고, 그것이 이 규칙의 강제 수단이다.
이 스킬은 **후보와 초안**을 내놓을 뿐 정답을 확정하지 않는다.

승격 기준: 그 실패가 (a) 이미 한 번 실제로 일어났고 (b) 결정론적으로 판정
가능하면 auto rubric으로, (c) 판정에 추론이 필요하면 judge rubric으로.
(b)도 (c)도 아니면 골든이 아니라 회고 메모다.

## Phase 6: 산출

`harness/reports/<ISO주차>.md`에 아래 순서로 쓴다.

1. **force 비율** (5% 초과면 굵게)
2. M1~M3·M5~M8 값 + 원천 + 지난 주 대비
3. 실패 3모집단 분류와 건수
4. 골든 승격 후보 (초안 rubric 포함, 확정 아님)
5. **다음 주에 볼 것 1개** — 여러 개 쓰면 다음 주에 아무것도 안 본다

리포트는 커밋한다. 지표는 추세로만 의미가 있고, 추세는 이력이 있어야 보인다.

## 에러 핸들링

| 상황 | 처리 |
|---|---|
| 트레이스 로그가 비어 있음 | 훅이 죽어 있을 수 있다. `harness-audit`의 `hooks-selftest`로 넘긴다 |
| 지표 하나를 계산할 수 없음 | 값을 지어내지 않는다. "측정 불가 + 이유"로 기록한다 |
| 5분을 초과함 | 지표를 줄인다. 줄인 지표와 이유를 `metrics-baseline.md`에 남긴다 — M4가 그렇게 삭제됐다 |
| 이번 주 변경이 0건 | 리포트를 건너뛰지 말고 "변경 없음"으로 한 줄 남긴다. 공백과 무변경은 다르다 |

> **미검증 (2026-07-27)**: `scripts/metrics.mjs`·`scripts/phase-audit.mjs`는
> 아직 저장소에 없다. 스크립트가 생기기 전에는 Phase 1을 수동 집계로 대체하고,
> 그 사실을 리포트에 명시한다.
