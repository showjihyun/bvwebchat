# Retro Metrics — 주간 학습 루프

**이것은 게이트가 아니다.** `harness-audit`과 합치지 않은 이유가 그것이다 —
합치면 회고가 게이트처럼 느껴져 미뤄지고, 게이트가 선택처럼 느껴져 건너뛰게 된다.
여기서는 아무것도 차단하지 않는다. 재고, 분류하고, 다음 주의 후보를 낸다.

주기: 주 1회. **5분 안에 끝나지 않으면 지표를 줄인다** (자를 순서는 M5 → M6).

## Phase 1: 실측

```
node scripts/metrics.mjs report
```

산출물은 `harness/reports/<ISO주차>.md`다. `harness/metrics-baseline.md`에는
**값을 적지 않는다** — 정의만 있는 문서로 유지하는 것이 빈 칸 드리프트의
구조적 해소다.

**리포트도 스냅샷이다.** `metrics.mjs`는 실행할 때마다 현재 로그를 다시 읽으므로
행마다 시점이 다를 수 있다. 그래서 두 규칙을 지킨다:

- **에이전트가 동시에 도는 중에 잰 값은 베이스라인이 아니다.** 게이트를 치는
  주체가 늘어나는 동안 M8은 단조 증가하고, flake는 부하에 비례한다.
- 작업 웨이브가 끝난 뒤 `report`를 **다시 돌려 덮어쓴다.** 그때 전 행이 같은
  시점으로 맞춰지고, 그것이 공식 베이스라인이다.

원천이 셋이라는 것을 리포트에 명시한다. 원천이 다르면 신뢰 수준도 다르다.

| 원천 | 지표 | 주의 |
|---|---|---|
| git | M2 · M5 · M7 | 다른 머신에서 재계산 가능 |
| `phase.jsonl` (커밋됨) | M1(부분) · M3 | 프록시가 아니라 정확한 값 |
| 트레이스 (gitignore) | M6 · M8 | **로컬 전용** — 어느 머신·어느 기간인지 함께 적는다 |
| `harness/recurrence.md` (커밋됨) | 반복 원인 누적 | 지표가 아니라 **대장**이다. 회고에서 이번 주 실패를 분류할 때 **이미 있는 행인지 먼저 본다** — 2회째면 그 자리에서 처방한다. `policy-lint` P11이 미처방을 차단하므로 회고를 건너뛰면 다음 하네스 변경이 막힌다 |

**처방을 새로 쓸 때 반드시 물을 것: 기존 처방과 당기는 방향이 반대인가?**
2026-07-28 에 R4(체크포인트 미커밋)의 `Guide` 처방이 **쓴 다음 실행에서 실패**했다.
절차를 몰라서가 아니라 R3(커밋 오염 → *"`git commit -- <경로>` 만 쓴다"*)를 정확히
지킨 결과였다 — pathspec 을 좁게 쓸수록 상태 파일이 커밋에서 빠진다.
R3 는 "적게 실어라", R4 는 "이것도 실어라"인데 **둘을 조정하는 자리가 없었고 사람의
기억이 그 자리를 대신하고 있었다. 기억은 규칙이 둘일 때 가장 먼저 진다.**
지금 대장에는 이 충돌을 찾는 검사가 없다 — 회고가 그 자리다.

**시험이 떨어뜨렸을 때 먼저 가른다: 작성자를 고칠 것인가, 시험을 고칠 것인가?**
가르는 질문은 하나다 — ***"독자에게도 나쁜가, 점수에만 나쁜가."*** 후자면 시험이 틀렸다.
2026-07-28 에 재개 시험이 세 번 떨어뜨렸고 나는 세션 작성 규칙을 셋 늘렸다.
6차 재리뷰가 **둘은 채점기 문제**라고 갈랐다 — 내가 쓴 근거 문장 자신이
*"읽는 쪽은 다음 행동으로 세지 않는다 — 당연하다. 그런데 채점은…"* 이었다.
**독자가 옳게 행동하는데 점수가 떨어지면 고쳐야 할 것은 작성자가 아니다.**
회고가 이 구분을 하는 자리다 — 실패한 주에는 규율을 늘리고 싶어지고, 그때 시험이
틀렸을 가능성을 묻는 사람이 없다.

**그리고 처방이 게이트라면: 음성 시험의 차단 쪽에 `통과값 + 부정어` 형태가 있는가?**
R2 의 처방(`--self-test` 동봉)을 쓴 뒤에도 두 번 뚫렸고 **두 번 다 시험은 있었고
케이스가 없었다.** `미완료`(=`완료`+부정 접두)·`완료 예정`(=`완료`+미래)이 그 형상이다.
통과해야 할 값만 시험하면 이 계열은 영원히 안 잡힌다.

## Phase 2: 최상단에 올릴 것 — force 비율

리포트 맨 위에 **`force` 비율**을 쓴다 (`python harness/phase.py why`가 직접 출력).

> **5% 초과는 에이전트 문제가 아니라 매트릭스가 틀렸다는 신호다.**
> 처방은 사람의 인내가 아니라 정책 수정이다.

`forced:true` 전이가 있으면 각각의 `reason`을 그대로 인용한다. 사유를 요약하지
않는다 — 요약하는 순간 "급해서"가 "일정 압박"이 되고 패턴이 안 보인다.

## Phase 3: M8과 함께 읽기 — 게이트가 하중을 받는가

M8(게이트 차단 횟수)이 **0이면 둘 중 하나이고 둘 다 알아야 한다**:

1. 게이트가 무의미하다 — 아무도 그 경로를 쓰려 하지 않는다 → **제거 후보**.
2. 우회되고 있다 — Bash로 빠져나가고 있다 → **조사 대상**.

판별: `phase-audit.mjs`가 git 이력에서 단계 순서를 독립 재유도한다. 차단 기록은
없는데 이력상 순서가 어긋나 있으면 2번이다.

M8이 특정 경로에 몰려 있으면 그것은 **매트릭스가 틀렸다는 신호**이지 에이전트가
말을 안 듣는다는 신호가 아니다. 정당한 작업이 반복해서 막히면 경로를 연다.

## Phase 4: 실패 분류

`.harness/logs/tools.jsonl`(실패·차단만)과 `trajectory.jsonl`을 훑어 이번 주의
실패를 세 모집단으로 나눈다. **섞으면 처방이 섞인다.**

| 모집단 | 신호 | 처방 주체 |
|---|---|---|
| 환경·배선 파손 | 훅 에러, 스크립트 부재, 인코딩 실패 | 하네스 (`harness-audit`) |
| 정책 차단 | `blocked[]` — 게이트가 의도대로 막음 | 판단: 정당한 차단인가, 매트릭스 오류인가 |
| 헤맴 | `file_edit_counts` 상위 — 같은 파일 6번 수정, Edit 3연속 실패 | 컨텍스트·프롬프트 (테스트는 전부 초록이어도 나타난다) |

테스트 실패는 별도다. `check.mjs --repeat N`이 `assert`/`collect`/`crash`로
분류한다. **`assert` 외의 실패를 "flake"로 뭉뚱그리지 않는다** — 조용히
건너뛴 스위트는 "리팩터가 테스트 로드를 깨뜨렸다"와 구별되지 않는다.

## Phase 5: 골든 승격 후보

이번 주 이상했던 세션의 **입력**을 골든 케이스 후보로 뽑는다. 승격 루프가
작동한다는 증거가 M7이다.

- 트랙 A(제품 행동) 후보 → `evals/golden/track-a-product.jsonl`
- 트랙 B(하네스 행동) 후보 → `evals/golden/track-b-harness.jsonl`

**정답(then/rubric)은 반드시 사람이 쓴다.** 강제 수단은 `permissions` 가 아니라
**단계 매트릭스**다 — `evals/golden/**` 쓰기는 `SPEC` 에서만 열리고 평가받는 중
(`RED`·`GREEN`·`EVAL`·`REVIEW`)에는 막힌다. 이 스킬은 **후보와 초안**을 내놓을 뿐
정답을 확정하지 않는다.

승격 기준: 그 실패가 (a) 이미 한 번 실제로 일어났고 (b) 결정론적으로 판정
가능하면 auto rubric으로, (c) 판정에 추론이 필요하면 judge rubric으로.
(b)도 (c)도 아니면 골든이 아니라 회고 메모다.

## Phase 6: 산출

`harness/reports/<ISO주차>.md`에 아래 순서로 쓴다.

1. **force 비율** (5% 초과면 굵게)
2. M1~M3·M5~M8 값 + 원천 + 지난 주 대비
3. 실패 3모집단 분류와 건수
4. 골든 승격 후보 (초안 rubric 포함, 확정 아님)
5. **다음 주에 볼 것 1개** — 여러 개 쓰면 다음 주에 아무것도 안 본다

리포트는 커밋한다. 지표는 추세로만 의미가 있고, 추세는 이력이 있어야 보인다.

## 에러 핸들링

| 상황 | 처리 |
|---|---|
| 트레이스 로그가 비어 있음 | 훅이 죽어 있을 수 있다. `harness-audit`의 `hooks-selftest`로 넘긴다 |
| 지표 하나를 계산할 수 없음 | 값을 지어내지 않는다. "측정 불가 + 이유"로 기록한다 |
| 5분을 초과함 | 지표를 줄인다. 줄인 지표와 이유를 `metrics-baseline.md`에 남긴다 — M4가 그렇게 삭제됐다 |
| 이번 주 변경이 0건 | 리포트를 건너뛰지 말고 "변경 없음"으로 한 줄 남긴다. 공백과 무변경은 다르다 |

> **배선 상태 (2026-07-29 확인)**: `scripts/metrics.mjs`·`scripts/phase-audit.mjs`·
> `scripts/eval-b.mjs` 셋 다 실재한다. 첫 실측 리포트는 `harness/reports/2026-W31.md`.
> 트랙 B 러너가 실동작하므로 Phase 5의 승격 후보는 **바로 채점으로 이어진다** —
> 다만 골든 편집은 `SPEC` 단계에서만 가능하므로 이 스킬 안에서 확정할 수 없다.
> `phase-audit` 은 여전히 CI 미배선이다(`2bcaa28` 한 건으로 `exit 1`).

### 세 번째 질문 — **"내가 최근에 바꾼 것이 원인은 아닌가"**

앞의 두 질문(*"독자에게도 나쁜가"* · *"차단 쪽에 통과값+부정어가 있는가"*)을 다 적어
놓고 2026-07-29 에 이것을 빠뜨렸다. 재개 시험이 네 번째로 떨어지자 **채점기 결함을
근거로 케이스를 `blocked` 로 내렸는데**, 재리뷰가 체크포인트 51건의 앵커 수를 세어
**원인이 내가 직전에 넣은 세션 작성 규칙의 과잉 적용**임을 보였다. 되돌렸다.

**시험이 떨어뜨렸을 때 순서는 이렇다:**

1. **내가 최근에 바꾼 것이 원인인가** — 처방을 넣은 직후의 실패는 그 처방을 먼저 의심한다
2. 독자에게도 나쁜가, 점수에만 나쁜가 — 후자면 시험이 틀렸다
3. 시험을 고칠 거면: 차단 쪽 케이스에 `통과값 + 부정어` 형태가 있는가

**1번을 건너뛰면 2번이 자기변호의 도구가 된다.** `evals/README.md` 의 `blocked` 절과
`harness/recurrence.md` R7 이 같은 사건을 다른 각도로 적고 있다.

### 네 번째 — **이 센서는 내 머신에서만 참은 아닌가**

`harness/recurrence.md` R9: `doc-freshness` C4 가 `dist/server/main.js` 같은 빌드
산출물을 죽은 참조로 잡았다. 개발 머신에는 `npm run build` 결과가 남아 있어 **항상
초록**이었고, `ci.yml` 에 배선한 순간 15건이 터졌다. **사람이 손으로 부르는 센서는
그 사람의 환경에서만 참이다.**

회고에서 물을 것: 이번 주에 손으로만 돌린 검사가 있는가. 있으면 **CI 에 배선하거나,
왜 안 하는지를 `recurrence.md` 에 적는다.** 배선의 값어치는 실패를 잡는 것보다
**센서 자신의 결함을 드러내는 것**에 있다 — R8 의 처방이 R9 를 낳았다.

그리고 **같은 배선이 감사 스킬의 낡은 "미배선" 블록까지 잡았다**(R1). 그 블록은
*"배선을 바꾸면 이 블록을 같은 커밋에서 갱신하라"* 고 스스로 적어 두었는데도 안 고쳐졌다.
**세 줄기가 하나다**: R8(손으로만 부름) → 배선 → R9(환경 의존) → 배선 블록 낡음(R1).
자동으로 도는 센서만이 **자기를 설명하는 문장까지** 잰다.

### 다섯 번째 — **이 규칙의 유지 비용은 얼마인가**

`harness/recurrence.md` R10: `CLAUDE.md` 가 스킬 규칙을 재서술하고(→C2 의존) 동시에
`HASH_GLOBS` 에 있어(→아티팩트 무효), **스킬 한 줄 고치는 비용이 트랙 B 전수 재실행
(~\$8 · 20분)이 된다.** 두 규칙은 개별로 옳고 **곱해질 때만** 틀린다.

**그리고 이번 주에 미룬 처방이 있는가 — 그 유예 근거를 재봤는가.** `harness/recurrence.md`
R11: 유예 근거를 검증 없이 쓴 것이 세 번이고 **세 번 다 틀렸다** (대장의 R11 상세에
사례별 표가 있다 — *"같은 `ci.yml` 이라 같은 PR"* · *"헌법이라 별도 PR"*). *"별도 PR 이어야 한다"* 는
재보기 전까지 근거가 아니라 인상이다. `policy-lint` P11 이 차단하지만 **P11 이 물기 전에
스스로 재는 것**이 회고의 자리다.

회고에서 물을 것: 이번 주에 **같은 수렴을 두 번 이상** 했는가. 했으면 그것은 절차가
아니라 **결합**이고, 대장에 올린다. 규칙을 늘릴 때는 *"이 규칙이 기존 규칙과 곱해지면
비용이 어떻게 되는가"* 를 함께 본다 — 이 저장소는 그 곱셈을 다섯 번 겪고서야 세었다.
