# 반복 실패 대장

운영 규칙 3은 *"같은 실수가 2회 반복되면 센서 하나 **또는** Guide 한 줄"* 을 요구한다.
그런데 **누적을 세는 곳이 없었다.** 그래서 2026-07-27 하루에 같은 원인으로 3~9회를
반복하면서 매번 새로 발견했다 — 규칙은 알고 있었고 세는 자리가 없었다.

이 파일이 그 자리다. `scripts/policy-lint.mjs` 의 **P11** 이 읽어 **3회 이상인데 처방이
열려 있는 항목에서 exit 1** 을 낸다. `metrics.mjs` 가 아닌 이유: metrics 는 의도적으로
항상 exit 0 이다(*"지표 산출은 관측이지 판정이 아니다"*) — 관측과 차단은 다른 도구의 일이다.

## 쓰는 법

- 같은 원인으로 **2회**째면 행을 추가한다. 3회를 기다리지 않는다.
- `처방` 은 규칙 3에 따라 **하나만** 고른다: `구조`(불가능하게) · `게이트`(차단) ·
  `센서`(관측) · `Guide`(문서). 우선순위는 왼쪽이 높다.
- **`상태: 미처방` 인 채로 3회에 도달하면 `policy-lint` P11 이 차단한다.** 처방을 적는 것이
  해소 조건이지, 횟수가 줄기를 기다리는 것이 아니다.
- 처방이 실제로 먹혔는지는 `마지막 발생` 이 처방 날짜 이후로 갱신되는지로 본다.
  갱신되면 그 처방은 틀렸다.

## R1 상세 — 센서가 실패해 Guide 로 내려온 사례

**1차 처방(`센서` — `doc-freshness` C2 결합 낡음)은 실패했다.** C2 는 "이 PR 이 건드린
의존만 책임진다"로 범위를 좁혔는데, 그 좁힘 자체가 **게이트를 살려두려는 의도적 절충**
이었다(전체를 걸면 첫날부터 모든 PR 이 빨개진다). 대가가 115커밋 브랜치에서 청구됐다 —
범위가 사실상 비어 B-d 가 그대로 새어나갔다. **넓히면 게이트가 죽고 좁히면 이 실패가
남는 절충이라 센서로는 답이 없다.**

**2차 처방은 `Guide` 이되 게이트에 놓는다.** `harness-audit` Phase 3(변경 제안)에
필수 질문을 추가한다:

> **이 변경이 거짓으로 만드는 문장이 있는가?** 바꾼 정책값·경로·기본값을 `rg` 로
> 전수 검색해 그것을 인용하는 문서를 찾았는가? 찾은 것을 같은 커밋에서 고쳤는가?

Guide 가 센서보다 약하다는 것을 인정한다. 다만 **하네스 변경은 반드시 이 스킬을
거치므로** 병목에 놓인 Guide 이고, 그 점에서 자유롭게 떠도는 문서 규칙과 다르다.

**이 처방이 또 실패했는지 아는 법**: R1 의 `마지막 발생` 이 2026-07-28 이후로
갱신되면 실패한 것이다. 그때는 Guide 도 버리고 다른 것을 골라야 한다 —
후보는 "정책값을 문서에 재서술하지 않고 포인터로만 참조" 이지만 산문은 못 덮는다.

## R4 상세 — 구조 처방을 버린 이유

근본 해소는 `phase.py enter` 가 체크포인트를 **자동 커밋**하는 것이다. 버렸다:
`phase.py` 가 git 을 쓰기 시작하면 (a) 전이가 워킹트리 상태에 의존하게 되고
(b) 남의 스테이징을 실어 R3(커밋 오염)를 재발시키며 (c) 상태의 유일한 writer 라는
불변식이 "상태 + 이력의 writer" 로 넓어진다. **세 대가가 이 실패 한 건보다 크다.**

대신 운영 순서를 고정한다: **전이 → 커밋 → 평가.** `eval-b` 의 에러 메시지가 이미
정확히 이것을 말하고 있었는데(*"커밋되지 않은 내구 기록은 다른 머신에서 읽히지 않는다"*)
**순서가 어디에도 절차로 적혀 있지 않아** 세 번 반복했다 — 메시지는 증상을 말하고
절차는 순서를 말한다. 둘은 다르다.

## 오늘 배운 것 — 왜 세는 자리가 필요한가

R1 이 9회까지 간 이유는 **매번 다른 문서에서 발견됐기 때문**이다. 개별로 보면
`architecture-2026.html` 한 곳, 감사 스킬 한 곳, `tool-risk.json` 한 곳이라
각각은 사소한 오탈자로 보인다. **같은 원인이라는 것이 보이려면 누적이 필요하다.**

그리고 R1 의 처방(C2)이 **실패했다는 사실 자체가 이 대장의 존재 이유**다. 처방을
적어두지 않으면 "이미 고쳤다"고 믿은 채 같은 실패를 계속 낸다 — 실제로 B4 에서
고치고 B-d 로 재발했다.

**`상태` 칸이 ✅ 라고 끝난 것이 아니다.** 마지막 발생이 처방 날짜 이후로 갱신되면
그 처방은 틀렸고, 다시 골라야 한다.
