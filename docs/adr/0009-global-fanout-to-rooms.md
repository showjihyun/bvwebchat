# ADR-0009: global 메시지를 참여 중인 room 안에도 표시

- 상태: 승인
- 날짜: 2026-08-07
- 관련 스펙: RQ-04-a (RQ-04 보강), RQ-02, RQ-18
- 관계: **ADR-0004 결정 4를 대체한다.** ADR-0002(이력 링버퍼)·ADR-0008(global 참여자 예외)에 영향.

## 맥락

RQ-04는 *"접속 중인 모든 사용자에게 전달"* 만 요구했다. ADR-0004가 그것을
**전원 자동 참여하는 예약 상설 room**으로 모델링했고, 그래서 global 메시지는
`#global` 채널 하나에만 표시된다.

**스펙과 구현은 일치했다. 어긋난 것은 사용자의 기대였다.** 2026-08-07 실측:

```
A(sem-room-1) 수신 O · 도착 채널 global · 자기 room 에도 표시 X
B(sem-room-2) 수신 O · 도착 채널 global · 자기 room 에도 표시 X
```

*"모든 사용자에게 전달"*(수신 대상)과 *"모든 방에 표시"*(표시 위치)는 다른 요구다.
RQ-04는 전자만 정했고 후자는 **정한 적이 없다** — 구현이 임의로 좁힌 것이 아니라
스펙에 없던 축이다. 사용자가 후자를 원한다고 결정해 RQ-04-a로 명문화한다.

## 결정

global 메시지는 `#global`에 더해 **각 수신자가 참여 중인 모든 room 안에도** 표시된다.

1. **범위 — 수신자가 참여 중인 room에만.** 서버의 모든 room이 아니다.
2. **이력 — 각 room의 링버퍼에도 저장한다.** 새로고침·재접속 후에도 그 room에서 보인다.
3. **`#global` 채널은 유지한다.** 같은 메시지가 `#global`과 각 room 두 곳에 보인다.
4. **room 안의 global 메시지는 시각적으로 구분한다.**
5. **안 읽음(RQ-18)은 `#global`만 올린다.** 각 room의 안 읽음 수는 올리지 않는다.

## 근거

- **1 (범위)**: 참여하지 않은 room까지 넣으면 *"내가 없던 방에 내 글이 남는다"*가 되고,
  RQ-02(격리)가 그은 선을 global 예외가 넘어선다. 수신자 기준으로 좁히면 격리와
  충돌하지 않는다 — 어차피 그 사용자가 볼 수 있는 방이다. 또 빈 room·생성 시점
  경합을 다루지 않아도 된다(RQ-12가 빈 room을 지우므로 "모든 room"은 시점 의존이다).
- **2 (이력)**: 표시만 하고 저장하지 않으면 새로고침에서 사라져 *"방에 보인다"*는
  약속이 접속 중에만 참이 된다. 부분적으로만 참인 약속은 문서가 거짓말하는 자리가 된다.
- **3 (`#global` 유지)**: 없애면 ADR-0004의 예외 3건(RQ-12 존속·RQ-13 예약 이름·
  RQ-15 참여자)을 전부 다시 판단해야 하고, ADR-0008이 *"셋은 독립이 아니다"*라고
  적어 둔 결합을 풀어야 한다. 이 변경의 범위를 넘는다. **중복 표시를 감수한다.**
- **4 (구분)**: 구분이 없으면 그 방에서 한 말로 오인된다. 더 나쁜 것은 답장이다 —
  그 방에 답하면 global 발신자는 못 본다. 표시가 오해를 만들면 그것은 기능이 아니라 함정이다.
- **5 (안 읽음)**: 공지 하나에 참여 중인 방 전부가 동시에 빨간 점이 되면 배지가
  의미를 잃는다. 배지는 *"내가 놓친 대화"*를 가리켜야 하는데 global은 이미
  `#global`이 가리킨다. 두 곳이 같은 사건을 세면 사용자는 한 곳을 무시하게 된다.

## 버린 대안

- **클라이언트 합성** — 서버는 global 이력만 갖고 클라이언트가 방을 그릴 때 시간순으로
  섞어 보여 준다. 저장 중복이 0이라 매력적이지만, **표시가 클라이언트 구현에 걸린다**:
  다른 클라이언트(테스트 하네스·향후 앱)는 같은 화면을 못 만든다. 서버 계약이 *"방에
  보인다"*를 보장하지 못하면 통합 테스트가 UI를 통해서만 가능해진다.
- **저장하지 않고 실시간 표시만** — 새로고침에서 사라진다(결정 2의 근거 그대로).
- **모든 room에 전송(참여 여부 무관)** — 결정 1의 근거 그대로.
- **`#global` 폐지** — 결정 3의 근거 그대로.

## 결과

- **이력 중복이 ADR-0002의 room당 50건 한도를 잠식한다.** 방 N개에 참여한 사용자에게
  global 공지 1건은 링버퍼 N칸을 쓴다. **이 ADR은 한도를 바꾸지 않는다** — 실사용에서
  잠식이 문제가 되는지 재기 전에 숫자를 바꾸는 것은 근거 없는 조정이다.
  `docs/progress.md` 보류표에 등재하고 트리거를 적는다.
- 같은 메시지가 `#global`과 각 room에 보인다 — 결정 3의 대가이고 결정 4가 그 오해를 막는다.
- `docs/design/DESIGN.md`에 room 안 global 메시지의 표시 규칙이 추가된다.
- 골든 케이스 신설 대상: *"방에 있는 사용자가 global 메시지를 그 방에서 본다"* ·
  *"새로고침 후에도 그 방에 남는다"* · *"참여하지 않은 방에는 안 들어간다"* ·
  *"각 방의 안 읽음은 안 오른다"*.
- **RQ-02 격리는 그대로다** — global 사본은 수신자가 참여한 room으로만 가므로
  비참여자에게 새지 않는다. 격리 테스트는 이 예외를 포함해 다시 확인해야 한다.
